# Disposition of Codex review 08 (presets follow-up)

Review: [response-08-presets-follow-up.md](response-08-presets-follow-up.md),
of draft 3 of [presets.md](../presets.md) (today's timeline as an ordinary
preset file; unfolding one lane into its streams). Verdict: keep both
decisions and the single lane mechanism; unfolding was not ready as written.
All 13 findings are accepted and folded into draft 4 (2026-11-18). Nothing is
built yet; §13 of the design lists the tests the implementation must bring,
including each case the review reproduced.

| Finding | Disposition | Where (presets.md) |
|---|---|---|
| 1. 200 runs is not a read bound | Accepted. Budgets for runs (default lowered to 50), streams per run, events per stream (refused before reading from a closed run's `stop.num_events`, cut off for open streams), time per request; reads shared and throttled per run; a bounded cache. The design states that Tiled 0.2.21 cannot select rows or compute extrema, so the server's work can only be refused, not bounded; a min/max read upstream would remove that. A dedicated stream-time read in `layout.py` (no `seq_num`, no sort) | §6.5, §12 |
| 2. Status cannot report unfolding | Accepted. The frame and Data status get the same `preset`, range and `unfold`, share reads, and the status reports the lane, runs unfolded and left folded, empty, pending, invalid, unreadable and refused streams, stale extents and budgets; these are completeness issues, never run failures or health | §6.5, §10, §11 |
| 3. `has_table` excludes processing streams | Accepted. Unfolding reads every stream's `internal` time column, including external-only streams; empty, pending and unreadable are told apart, not inferred from `has_table`, which is renamed for what it means; activity's rule is unchanged | §6.5, §8, §12 |
| 4. Stream geometry | Accepted. Stream rows span the earliest to the latest finite event, also for open runs; single events are widened for visibility only; overlaps use true extents; run state, activity and freshness stay separate fields; Zoom to run keeps the run's extent; the tooltip names the stream and that the outcome is the run's; the span is an event-time span, not a duty cycle | §6.5 |
| 5. Replacement, overlap, caps | Accepted, as recommended: only the clicked placement's lane unfolds; its latest runs become stream rows (by stream, overlaps per stream, ties by start, root, uid); older runs and runs with nothing drawable stay on a folded `· earlier runs` row; all rows count against budgets, padding after; the latest-runs table and trend are unchanged by unfolding | §6.5, §10 |
| 6. Closed-run caching | Accepted. The first sight of a closed run forces a fresh complete read; only that is kept, keyed by root, uid and stop document, and only if row counts match `stop.num_events`; errors are retried and last good extents shown as stale; the immutability assumption is stated for Bluesky 1.14.6's `TiledWriter`, with a revalidation setting for other producers | §6.5 |
| 7. Template grammar | Accepted, simplified: templates are a string or a list of parts; parts are trimmed, empty parts dropped and the rest joined with ` · `; that is the only clean-up, so values (with their own ` · `) are kept as written. `{path|default}` with `{`, `}`, `|` rejected in defaults; `{{`/`}}` literal braces; lane names render canonical components; an all-empty name falls back to the joined components, then `(unknown)` | §6.2, §6.4 |
| 8. The default changes run inclusion | Accepted: `group_by.invalid` (`exclude` by default, `missing` in the shipped default), so list- or mapping-valued identity fields keep today's behaviour, now reported. The root's effect on lanes and trend peers, and processing adjacency only within one root, are recorded in §4.1's table | §4, §4.1, §6.2 |
| 9. Final names | Accepted: one allocator for every frame row (logical lanes, stream rows, overlap sub-lanes, padding), names reserved before suffixes; ids, never names, in links; base names cut to 180 characters so suffixes fit 200; root and facility in tooltips | §6.2 |
| 10. Summaries and trends | Accepted. "First placement" is the first in `lanes.order`; `/clips.label` stays the view table's run label; run summaries' `lane` is the base name in the default preset; both trend routes take `lane`, with the same direct-link rule; "as today" removed; disposition 07's preserved-fields statement superseded by this row and §10 | §10 |
| 11. Same key in two roots | Accepted. Runs are `(root, uid)`: rows carry `root`, the dashboard has a `root` variable, run and selection endpoints take an optional `root`; without it, the lookup is as now but a key found under two roots is reported as ambiguous, never resolved silently | §10, §11 |
| 12. Links | Accepted: the generator builds navigation from one transition table (each variable once, kept or replaced from row fields by id); Unfold and Fold both on every clip (no per-row visibility in Grafana 13.3.1), plus a Fold link in the header; helper columns declared and hidden; browser round-trip tests on the pinned stack | §11, §13 |
| 13. Defaults and packaging | Accepted: `instruments` stays reserved and is loaded with the same parser and validator; `ETT_DEFAULT_PRESET` picks the default, listed first by `/presets` so the picker starts there; the YAML is package data, tested from an installed wheel; lexicographic, type-ordered group sorting | §2, §6.2, §11, §13 |
